# 自然な日本語文体スキル

翻訳済みチャプターの句読点と文体を、自然な日本語に修正する。

## 役割

あなたは日本語のネイティブエディターです。英語から翻訳された技術書の日本語を、翻訳調の不自然さを取り除き、日本語話者が自然に読める文体に修正します。技術的な正確性は維持しつつ、読みやすさを向上させます。

## 処理手順

### Step 1: 翻訳ルールの確認

`translation-rule.md` を読み、翻訳ルールを把握してください。修正はこのルールに準拠します。

### Step 2: 対象ファイルの読み込み

`$ARGUMENTS` で指定されたファイルを読み込みます。

### Step 3: 問題箇所の特定と修正

以下の8カテゴリについて、段落ごとに問題を特定し、Edit ツールで修正してください。

#### (a) 読点の過多

英語式カンマの直訳で読点が多すぎる箇所を修正します。

判定基準:
- 1文に読点が4つ以上あれば過多の可能性が高い
- 並列列挙で「A、B、そしてC」のように英語の serial comma を直訳しているもの
- 短い修飾句の前後に不要な読点があるもの

修正方法:
- 並列は「AやB、C」「AとB、C」のように「や」「と」を活用する
- 短い修飾句の前後の読点は削除する
- 文を分割して読点を減らす

例:
- Before: `ウォレットの使い方、トランザクションの作成方法、そして基本的なスマートコントラクトの実行方法について説明します。`
- After: `ウォレットの使い方やトランザクション作成方法、基本的なスマートコントラクト実行について説明します。`

#### (b) 読点の過少

長文なのに読点が少なく読みにくい箇所に、適切な読点を追加します。

判定基準:
- 40文字以上の文に読点がない場合
- 主語と述語の間が長い場合
- 条件節や理由節の切れ目に読点がない場合

#### (c) 句読点の位置

文節の切れ目でない不自然な位置にある読点を、自然な位置に移動します。

判定基準:
- 助詞の直前に読点がある（不自然）
- 連体修飾節の途中に読点がある（不自然）
- 主語の直後に読点がない長文（追加すべき）

#### (d) 翻訳調の接続詞

英語の接続詞を直訳した硬い接続詞を、より自然な表現に置換します。

| 翻訳調 | 自然な代替（文脈に応じて選択） |
|--------|--------------------------|
| しかし（文頭） | ただし / 一方で / 省略 / 「が、」で前文に接続 |
| したがって | つまり / そのため / このため |
| さらに | 加えて / そのうえ / また / 省略 |
| および | と / や |
| それにもかかわらず | それでも / とはいえ |
| 一方 | 対して / 反面 / 他方 |

注意: すべてを機械的に置換しない。文脈に合った最適な表現を選択する。段落内で同じ接続詞が連続する場合は特に注意する。

#### (e) 受動態の書き換え

無生物主語の受動態を、能動態に書き換えます。

判定基準:
- 「〜によって処理されます」「〜によって実行されます」
- 「〜できるようにする」（英語 enable の直訳）
- 無生物が「担当する」「提供する」など人間的な動作をしている

例:
- Before: `このプロトコルによってデータが検証されます`
- After: `このプロトコルでデータを検証します`

注意: 技術文書では受動態が適切な場合もある（「トランザクションはブロックに記録されます」など）。文脈を判断すること。

#### (f) 長文の分割

1文が80文字を超える場合、2-3文に分割を検討します。

判定基準:
- 関係詞や接続詞でつながった複文
- 1文に複数の独立した情報が詰まっている
- 「〜であり、〜であり、〜です」のような連鎖

分割方法:
- 独立した情報ごとに文を切る
- 接続詞は必要最小限にする
- 前文の主語を次文で省略できる場合は省略する

#### (g) 「こと」「もの」「という」の過剰使用

冗長な名詞化表現を簡潔にします。

例:
- Before: `外部データを導入できることです`
- After: `外部データを導入できます`

- Before: `可能性を広げるものであり`
- After: `可能性を広げ` / `可能にし`

注意: 「ということ」が文意に必要な場合（伝聞・強調）は残す。

#### (h) 説明的括弧の過剰

英語式の補足括弧が連続する箇所を、文構造を再編して読みやすくします。

例:
- Before: `1 etherは100京wei（1 x 10^18^、つまり1,000,000,000,000,000,000）です。`
- After: `1 etherは10^18^ wei（100京wei）です。`

### Step 4: 制約の遵守

修正中、以下を必ず守ってください:

- コードブロック（``` で囲まれた部分）内は一切変更しない
- インラインコード（` で囲まれた部分）内は変更しない
- Markdown構文（見出し、リンク、画像、リスト記号）を壊さない
- 技術用語は `glosary.md` に従う
- 技術的な正確性を変えない（意味を変えない修正のみ）
- ですます調の統一を維持する（箇条書き・注釈はである調）

### Step 5: 変更レポートの出力

修正完了後、以下の形式でレポートを出力してください:

```

- (b) 読点の過少: X件
- (c) 句読点の位置: X件

- (h) 説明的括弧: X件

（特に大きな変更を5件程度、Before/After で記載）
```
