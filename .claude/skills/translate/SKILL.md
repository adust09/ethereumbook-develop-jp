# 翻訳スキル — Mastering Ethereum 2nd Edition 日本語翻訳

## 役割

あなたは「Mastering Ethereum: Building Smart Contracts and DApps, 2nd Edition」（O'Reilly）の日本語翻訳者です。初版で確立された翻訳ルール・用語・人名表記を引き継ぎつつ、高品質な日本語翻訳を行います。

## 翻訳手順

### Step 1: 翻訳ルールの把握

`translation-rule.md` を読み、以下の翻訳ルールを把握してください。

1. ですます調で翻訳。タイトルは体言止め。箇条書き・注釈はである調
2. 英数字は半角、カタカナは全角
3. 複合語は半角スペースで区切る（例: コンピューター システム）。人名は「・」で区切る
4. （）などの記号類は全角。！？は感情表現がある箇所以外は使用しない
5. タイトル・見出しの文末には句読点を使わない
6. 英単語と日本語の間のスペースは不要
7. 訳注は〔訳注：●●●●〕の形式でテキスト本文に挿入
8. 段落の開始時は文頭に全角スペースを入れる
9. 長文は適宜2〜3文に分割する（特に関係詞・接続詞でつながった文）
10. 無生物を主語にした受動態の文は避ける
11. 英文のニュアンスは大事にするが、読みにくい直訳は避ける
12. 意味がわからない場合は英文のままにしておき、グループに意見を聞く
13. 指示代名詞・人称代名詞は具体的な固有名詞で置き換え、できるだけ減らす

### Step 2: 用語対訳の把握

`glosary.md` を読み、既存の英語→日本語の用語対訳を把握してください。翻訳中は必ずこの用語集に従ってください。

### Step 3: 人名表記の把握

`people.md` を読み、既存の人名カタカナ表記を把握してください。翻訳中は必ずこの人名表に従ってください。

### Step 4: チャプターの翻訳

`$ARGUMENTS` で指定されたファイルを読み込み、日本語に翻訳します。

**翻訳時の注意事項:**

- Markdownの構文（見出し `#`、リスト `- / *`、コードブロック `` ``` ``、リンク `[]()`、画像 `![]()` など）はそのまま維持する
- コードブロック内のコード自体は翻訳しない。コードブロック内のコメントは日本語に翻訳する
- 技術用語は `glosary.md` に従う。用語集で英語のまま残す指定のもの（例: proof-of-work, Solidity）はそのまま英語で記載する
- 人名は `people.md` に従いカタカナ表記する
- 画像パスやファイル参照はそのまま維持する
- アンカーリンクやクロスリファレンスはそのまま維持する

### Step 5: 新規用語・人名の管理

翻訳中に以下を発見した場合、対応するファイルを更新します。

**新規用語の場合（`glosary.md` にない英語用語）:**

1. 適切な日本語訳を決定する
2. `glosary.md` のテーブル末尾に以下の形式で追加する:

```
| English Term | 日本語訳 |
```

**新規人名の場合（`people.md` にない人名）:**

1. カタカナ読みを決定する（可能であれば発音動画や辞書を参考にする）
2. `people.md` のテーブル末尾に以下の形式で追加する:

```
| Name | カタカナ表記 | カナふり方法 | 参考URL1 | 参考URL2 |
```

- カナふり方法や参考URLが不明な場合は空欄で構いません

### Step 6: 翻訳結果の出力

翻訳が完了したら、翻訳済みテキストで元のファイル（`$ARGUMENTS`）を上書きしてください。

## 翻訳品質チェックリスト

翻訳完了後、以下を確認してください:

- [ ] ですます調が統一されている（箇条書き・注釈はである調）
- [ ] `glosary.md` の用語が正しく使われている
- [ ] `people.md` の人名表記が正しく使われている
- [ ] Markdown構文が壊れていない
- [ ] コードブロック内のコードが変更されていない（コメントのみ翻訳）
- [ ] 新規用語が `glosary.md` に追加されている
- [ ] 新規人名が `people.md` に追加されている
- [ ] 段落開始時に全角スペースがある
- [ ] 長文が適切に分割されている
- [ ] 不自然な直訳がない
