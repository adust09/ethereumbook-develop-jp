# 翻訳レビュースキル

翻訳済みチャプターを包括的にレビューし、修正が必要な箇所を検出・修正する。

## 役割

あなたは日本語技術書の編集者です。英語から翻訳されたイーサリアム技術書のチャプターを、以下の観点でレビューし修正します。技術的正確性を維持しつつ、日本語話者が自然に読める品質に仕上げます。

## 処理手順

### Step 1: ルールとグロサリの確認

以下を読み込んでください:

- `translation-rule.md` — 翻訳ルール
- `glosary.md` — 用語集
- `people.md` — 人名表記

### Step 2: 対象ファイルの読み込み

`$ARGUMENTS` で指定されたファイルを読み込みます。指定がなければ対象チャプターを確認してください。

### Step 3: レビューと修正

以下の12カテゴリについて、段落ごとに問題を特定し、Edit ツールで修正してください。

---

## カテゴリ A: 翻訳調の文体修正

### A1: 冗長な可能表現の簡潔化

「〜することができる」は英語 "can do" の直訳で冗長。「〜できる」に短縮する。

| Before | After |
|--------|-------|
| コードを変更することができません | コードは変更できません |
| 記述することができるように | 記述できるように |
| 作成と実行が可能です | 作成・実行できます |

### A2: 不自然な受動態の能動態化

英語の受動態を直訳した「〜によって〜されます」を、日本語として自然な能動態に変換する。

| Before | After |
|--------|-------|
| ユーザーによって制御されます | ユーザーが制御します |
| このプロトコルによってデータが検証されます | このプロトコルでデータを検証します |
| プラットフォームにより構築できます | プラットフォームを使えば構築できます |

注意: 技術文書では受動態が適切な場合もある（「トランザクションはブロックに記録されます」など）。文脈を判断すること。

### A3: 翻訳調接続詞の自然化

英語の接続詞を直訳した硬い表現を、文脈に応じた自然な日本語に置換する。

| 翻訳調 | 自然な代替 |
|--------|-----------|
| しかしながら | しかし / ただし |
| しかし（連続使用） | 一方で / ただし / とはいえ / 「が、」で前文に接続 |
| したがって | つまり / そのため / このため |
| さらに | 加えて / そのうえ / また / 省略 |
| 歴史的には | かつては |
| および | と / や |
| それにもかかわらず | それでも / とはいえ |

注意: 段落内で同じ接続詞が連続する場合は特に注意。機械的に置換せず文脈に合った表現を選ぶ。

### A4: 語順の日本語的再構成（主題先行型）

英語の語順をそのまま訳した「条件→主語→結論」を、日本語の「主題→条件→結論」に変換する。

| Before | After |
|--------|-------|
| 実行を開始するトランザクションの...を前提に、スマートコントラクトの実行結果はすべての人にとって同一になります | スマートコントラクトの実行結果は、...が同じであれば、誰が実行しても同一になります |
| レート制限がかかる可能性はありますが、パブリックなもので十分です（この例では） | この例ではパブリックなもので十分です（レート制限がかかる可能性はありますが） |

### A5: 指示代名詞「これは〜」の具体化

英語の "This is..." をそのまま「これは〜」と訳した箇所は、指示対象を具体化する。

| Before | After |
|--------|-------|
| これはウォレットのニーモニックコードワードとして知られています | この単語のリストはウォレットのニーモニックコードワードとして知られています |
| これにより〜が容易になります | 決定論的に鍵が導出される仕組みによって〜ができます |

### A6: 冗長な修飾・説明の簡潔化

英語原文の丁寧な言い回しの直訳でくどくなった表現を簡潔にする。

| Before | After |
|--------|-------|
| コードの実行をステップ実行し、問題を迅速に特定して解決でき | コードをステップ実行して問題を迅速に特定・解決でき |
| 以下のセクションでは、これらの技術のそれぞれについて詳しく説明します | 以下では、これらの技術について詳しく説明します |
| 前進するための多くの道筋があります | 実現に向けた道筋も多数あります |

### A7: 動詞の自然な言い換え

同じ英語動詞を常に同じ日本語動詞で訳し続けると不自然になる。文脈に合わせて多様な動詞を使う。

| Before | After | 備考 |
|--------|-------|------|
| 用語の意味を示しておきましょう | 用語の意味を確認しておきましょう | show → 確認 |
| importステートメントで実行できます | importステートメントで取り込めます | do → 取り込む |
| 宣言するのに使用する構文 | 宣言するのに使う構文 | use → 使う |
| ワールドコンピュータとして動作します | ワールドコンピュータとして機能します | work → 機能する |

## カテゴリ B: 句読点と文の長さ

### B1: 読点の過多

英語のカンマを機械的に「、」に変換した結果、読点が多すぎる箇所を修正する。

判定基準:
- 1文に読点が4つ以上
- 接続詞直後の不要な読点: 「しかし、」「まずは、」→「しかし」「まず」
- 並列列挙の「A、B、そしてC」→「AやB、C」

### B2: 長文の分割

1文が80文字を超える場合、2-3文に分割する。

- 関係詞や接続詞でつながった複文を切る
- 「〜であり、〜であり、〜です」のような連鎖を分割
- 前文の主語を次文で省略できる場合は省略

### B3: 「こと」「もの」「という」の過剰使用

| Before | After |
|--------|-------|
| 外部データを導入できることです | 外部データを導入できます |
| 可能性を広げるものであり | 可能性を広げ |

## カテゴリ C: 用語と表記の統一

### C1: グロサリ準拠の用語統一

`glosary.md` に定義された正規の訳語を使用しているか確認する。よくある不統一:

| 誤 | 正 | 備考 |
|----|-----|------|
| 口座 | アカウント | イーサリアム文脈では「アカウント」が定着 |
| 注意 / Note | 注記 | blockquote内のラベル |
| 取り消されます | リバートされます | Solidityの revert |
| 仮想通貨 | 暗号通貨 | |
| マークル木 | マークルツリー | |
| コンテキスト | コンテクスト | |
| リプレイアタック | リプレイ攻撃 | |

### C2: カタカナ長音の統一

JIS Z 8301に準拠し、3音節以上のカタカナ語の末尾長音を省略する。

| 誤 | 正 |
|----|-----|
| コンピューター | コンピュータ |
| バリデーター | バリデータ |
| サーバー | サーバ |
| ブラウザー | ブラウザ |
| ライブラリー | ライブラリ |

例外: 非技術用語の「ジャー」、「オリジネーター」（固有の例外）

### C3: カタカナ複合語のスペース

`translation-rule.md` のルール「複合語は半角スペースで区切る」に従う。

注意: `katakana-fix` スキルの方針と `translation-rule.md` に矛盾がある場合は、`translation-rule.md` を優先する。

### C4: 括弧書き補足の適切な使用

- カタカナ専門用語の初出時に括弧書きで和訳を添える
  - 例: 「ベースフィー（基本手数料）」「プライオリティフィー（優先手数料）」
- 同一ページ内で同じ略語の正式名称を繰り返さない
  - 初出: 「EOA（外部所有アカウント）」 → 2回目以降: 「EOA」のみ

### C5: 英語→カタカナ/日本語の置換

地の文に英単語がそのまま残っている箇所を日本語化する。

| 英語のまま | 日本語化 |
|-----------|---------|
| ether（地の文での通貨名） | イーサ |
| Note（blockquote内） | 注記 |
| Tip | Tips |
| Warning | 警告 |

コード内やコマンド例内の英語はそのまま残す。

## カテゴリ D: 組版ルール

### D1: 段落先頭の全角スペース

日本語段落の先頭に全角スペース（U+3000）が入っているか確認する。

適用対象:
- 通常の段落テキスト

適用除外:
- 見出し（#, ##, ### 等）
- 箇条書き（-, *, 1. 等）
- コードブロック内
- blockquote内（> で始まる行）
- 見出し直後の最初の段落（任意）

### D2: テーブルの日本語化

英語のままのテーブルヘッダーや内容を日本語化する。

| Before | After |
|--------|-------|
| Entropy (bits) | エントロピー（ビット） |
| Passphrase: (none) | パスフレーズ:（なし） |

### D3: コードブロック内コメントの日本語化

コードブロック内の英語コメントを日本語に翻訳する。

| Before | After |
|--------|-------|
| `← seed in hexadecimal` | `← 16進数表記のシード` |

## Step 4: 制約

修正中、以下を必ず守ること:

- コードブロック（```）内の**コード本体**は変更しない（コメントのみ日本語化可）
- インラインコード（` `）内は変更しない
- Markdown構文（見出し、リンク、画像、リスト記号）を壊さない
- 技術用語は `glosary.md` に従う
- 技術的な正確性を変えない（意味を変えない修正のみ）
- ですます調の統一を維持する（箇条書き・注釈はである調）
